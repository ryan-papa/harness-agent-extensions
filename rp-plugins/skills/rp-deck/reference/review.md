# rp-deck 독립 리뷰 프로토콜 (생성 후 검수 SSOT)

생성·보강한 장표를 **작성 에이전트가 아닌 독립 서브에이전트**가 평가한다. ⛔ 작성자 셀프리뷰 금지.
파이프라인 위치: 자가 린트([`design-rules.md`](design-rules.md) §10) 직후, push(적재) 직전.

## 1. 원칙

| 규칙 | 내용 |
|------|------|
| 독립성 | 리뷰어는 장표를 만든 에이전트와 분리된 **새 서브에이전트**. 작성 맥락·의도를 물려주지 않고 **대상 HTML과 규칙 파일 경로만** 준다. 리뷰어는 파일을 직접 읽어 판단한다 |
| 상한 2라운드 | R1 → 수정 → R2 → 수정 → 종료. R2 지적은 반영만, 추가 재요청 없음 |
| 조기 종료 | 어느 라운드든 actionable 지적 0건이면 다음 라운드 생략 |
| 판단은 메인 | 채택·보류는 메인(작성) 에이전트가 결정. 충돌 시 [`design-rules.md`](design-rules.md) 우선, 채택/보류 근거 1줄 로그 |
| ⏱ 건당 10분 | 리뷰어 **호출 1건당 상한 10분**. 라운드별 개별 적용(합산 아님) |
| 비차단 | 리뷰어가 실패하거나 **타임아웃되면** 1줄 기록 후 진행. ⛔ 재시도 없음. 장표 산출을 막지 않는다 |

## 2. 리뷰어 호출

Agent 툴(`subagent_type: general-purpose`)로 **새 서브에이전트**를 띄운다. 프롬프트는 §3 템플릿을 그대로 복사해 `{ }` 자리만 채운다 — 매 실행 프롬프트를 새로 짓지 않는다.

- 툴에 타임아웃 인자가 없으므로 **프롬프트 안의 "10분 상한" 문장으로 강제**한다(미완이면 그 시점까지의 평가만 반환).
- 경로는 전부 **절대경로**로 넘긴다. 리뷰어는 작성 대화를 못 보므로 상대경로·"방금 만든 파일" 같은 지시어는 통하지 않는다.
- 원문(원본 문서·조사 결과)이 파일로 있으면 그 경로도 넘긴다. 없으면 `{원문}` 줄을 빼고 항목 1은 "내부 정합성만" 판정하게 한다.

## 3. R1 프롬프트 템플릿 (그대로 복사)

```
너는 이 장표의 **검수자**다. 작성자가 아니다. 파일을 고치지 말고 지적만 반환한다.

## 읽을 파일 (전부 Read한 뒤 시작)
1. 대상 장표: {장표 HTML 절대경로}
2. 생성 규칙: {스킬경로}/reference/design-rules.md
3. 시각 매핑: {스킬경로}/reference/visual-patterns.md
4. 원문 근거: {원문 파일 절대경로 — 없으면 이 줄 삭제}

## 방법
- HTML의 `<section class="slide">`를 문서 순서대로 1번부터 센다. 모든 지적에 이 **슬라이드 번호**를 붙인다.
- 규칙 위반은 반드시 `design-rules.md §N` 또는 `visual-patterns.md §N`으로 **근거 조항을 찍는다**. 조항을 못 찍는 지적은 취향이므로 버린다.
- 인상 비평("전반적으로 좋아요", "더 임팩트 있게") 금지. 어느 장의 무엇을 어떻게 바꿀지까지 쓴다.
- 원문에 없는 사실·수치를 새로 지어내 제안하지 않는다.

## 평가 항목 (10개 전부, 항목당 최소 1줄 판정)
1. **내용 정확성** — 원문 대비 사실 오류·누락·왜곡. 수치·고유명사·버전이 원문과 일치하는지. 원문이 없으면 덱 안에서 앞뒤 수치가 어긋나지 않는지.
2. **구조·전달력** — 결론 먼저(Minto), 도입 SCQA, 한 장 한 메시지, 목차·섹션이 주제 라벨이 아닌 주장인지, 긴장→해소 흐름인지. (`design-rules.md` §1·§2)
3. **비전공 이해도** — 그 기술을 처음 듣는 기획자·비전공 4학년이 혼자 읽는다고 가정한다. **멈칫할 지점을 슬라이드 번호로 지목**한다. "왜 필요한지"가 "어떻게 동작하는지"보다 앞인지, 첫 등장 용어를 그 자리에서 푸는지, 처음 나오는 핵심 도구에 소개 장이 있는지, **개념 도약이 가장 큰 장에 `.plain`이 붙어 있는지**. (§0·§9)
4. **시각 요소** — 스키마·데이터흐름·값 변화·기술 비교·계층 구조·추세·구성비를 `visual-patterns.md` §2 매핑표가 지정한 전용 컴포넌트로 그렸는지, **그림 없는 슬라이드가 연속 3장을 넘지 않는지**, 다이어그램에 추상 라벨 대신 실제 컬럼명·값이 들어갔는지, 비교·수치가 문장에 흘러가지 않고 표·차트·공식으로 옮겨졌는지. (§3)
5. **레이아웃 안전** — 각 슬라이드가 **1280×720 안에 들어가는지**. `visual-patterns.md` §7 높이 예산으로 직계 자식 높이를 더해본다(각주 있는 장은 본문 예산 488px, 없으면 576px). 초과 의심 장은 번호와 추정 높이를 적는다. "코드 블록 2개+각주", "표 5행+부연+각주", `.two-col` 안의 `.code`를 특히 본다.
6. **디자인·일관성** — 디자인 토큰 준수, 시각 위계(장마다 지배 요소 1개), 대비·여백, 장간 타입스케일 일관, 차트 정크·범례 의존·축 왜곡 없음, `.gloss` 쓰는 `<section>`에 `has-gloss` 클래스. (§2·§3·§7)
   **손으로 그린 인라인 SVG는 좌표를 직접 본다** — 블록이 전부 x=0에서 시작하는지(라벨 열이 있는 막대·리스트도 라벨이 x=0인지), 인접 `<text>`의 y 간격이 글자 크기보다 넓은지, viewBox 밖으로 나간 요소가 없는지. `python3 {스킬경로}/scripts/lint_svg.py {장표 HTML 절대경로}`를 돌려 결과를 근거로 삼는다. (`visual-patterns.md` §8)
7. **토스 톤·헤드라인** — 전 카피 해요체·문장형·긍정형·능동형. 명사 라벨("개요")·명사형 종결("송금 완료") 금지. **헤드라인마다 대상(기술·제품) 이름이 있어 제목만 봐도 주제가 잡히는지.** (§2·§6)
8. **부가 설명·용어** — 낯선 용어에 하단 각주가 충분한지(슬라이드당 2~5개), 약어 풀텍스트 병기, 각주 4줄 이내, **어려운 용어를 앞에서 설명했더라도 다시 나온 장에서 또 푸는지**, 용어 8개 이상인 덱에 마무리 직전 용어집(`.terms`)이 있는지. (§8)
9. **코드·주장 정합성** — 코드 예제가 그대로 복사해 컴파일·실행되는 형태인지(줄인 부분은 `.cmt`에 명시), **캡션·헤드라인이 주장하는 동작이 그 장의 코드·그림에 실제로 보이는지**, 앞 장의 판정과 뒤 장의 해법이 모순되지 않는지, "항상·무조건·~만" 단정에 반례가 없는지, 인용 사례에 출처와 **결말**이 있는지, 예시값에 "예시" 표기가 있는지. (§11)
10. **자가 린트** — `design-rules.md` §10 체크리스트를 순서대로 훑어 위반 항목만 나열한다.

## 반환 형식
아래 표만 반환한다. 서두·총평·격려 문구 없이 표부터 시작한다.

| 항목# | 심각도 | 슬라이드 | 문제 | 근거 조항 | 수정안 |
|---|---|---|---|---|---|

- 심각도: `high` = 사실 오류·주장과 코드 불일치·잘려서 안 보임·독자가 막힘 / `med` = 규칙 위반이지만 이해는 됨 / `low` = 다듬으면 좋음
- 지적이 하나도 없는 항목은 표에 넣지 말고, 마지막 줄에 `통과: 1,5,7`처럼 항목 번호만 적는다.
- **10분 안에 반환한다.** 시간이 모자라면 그 시점까지 본 항목만 표로 내고 마지막 줄에 `미검토: 8,9`를 적는다.
```

## 4. R2 프롬프트 (R1 템플릿 + 아래 블록 append)

```
## 이번은 2차 검수다
직전 검수에서 아래를 지적받아 고쳤다. 같은 지적을 반복하지 말고, **고친 결과가 실제로 해결됐는지**와 수정하며 새로 생긴 문제를 본다.

{채택한 지적과 수정 내용을 항목#·슬라이드 번호와 함께 1줄씩}

{보류 목록 1줄씩}
```

## 5. 루프

1. **R1** — §3 템플릿으로 서브에이전트 1회 호출 → 결과 수신.
2. **수정** — 메인 에이전트가 채택·보류를 판단(충돌=`design-rules.md` 우선)해 HTML에 반영. 채택/보류 근거를 1줄씩 로그.
3. **R2** — §4를 덧붙여 **1회 더** 호출 → 반영.
4. **종료** — R2 지적은 반영만. 남은 low 지적은 로그로 남기고 종료.

각 라운드에서 10분을 넘긴 리뷰어는 그 라운드에서 빠진다(재시도·연장 없음). 그 라운드는 지적 0건으로 보고 다음 단계로 넘어간다.

로그 예: `채택[R1-4]: 5장 추세를 표→선차트 · 채택[R1-5]: 9장 720px 초과로 장 분할 · 보류[R1-2]: 헤드라인 교체는 원문 근거상 현행 유지(design-rules §2 우선) · 타임아웃[R2]: 10분 초과, 스킵`.
