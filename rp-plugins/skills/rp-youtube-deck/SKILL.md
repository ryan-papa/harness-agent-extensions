# rp-youtube-deck — 유튜브 영상 → 검증 → 장표

영상 요약은 화자의 말을 그대로 옮기면 끝나지만, 장표는 남아서 인용된다. 영상이 인용한 원천을 직접 확인해 수치와 공식을 검증한 다음 장표로 만든다.

## 구성

이 스킬은 두 스킬을 순서대로 쓰는 오케스트레이터다. **각 단계에서 해당 스킬의 `SKILL.md`를 실제로 Read하고 그 규칙을 그대로 따른다.** 여기 요약된 내용으로 대체하지 않는다.

| 단계 | 사용 스킬 | 산출 |
|------|-----------|------|
| 1 | [`../rp-youtube/SKILL.md`](../rp-youtube/SKILL.md) | 정규화된 타임스탬프 전사본 + 구조·주장·수치·인용 출처 |
| 2 | (이 스킬 §원천 검증) | 영상 주장 ↔ 원천 문서 대조표 + 보강 자료 |
| 3 | [`../rp-deck/SKILL.md`](../rp-deck/SKILL.md) | HTML 장표 생성·리뷰·분류 적재·push·옵시디언 |

스킬 경로는 이 파일 기준 형제 디렉터리다. 찾지 못하면 중단하고 알린다(⛔ 규칙을 기억으로 재구성하지 않는다).

## 입력

| 인자 | 동작 |
|------|------|
| 유튜브 URL | 그 영상으로 전체 파이프라인 실행 |
| URL + 주문 (`실무 가이드로`·`20장 정도로`) | 그 주문을 장표 설계에 반영 |
| 없음 | **링크를 한 번 물어본다.** ⛔ 추측 금지 |

## 워크플로우

1. **타깃 레포 확인·최신화** — `rp-deck` §워크플로우 1과 동일. `.rp-deck.json`을 읽고 캐시를 원격 최신으로 강제 동기화한다. ⛔ 이 동기화 전에 생성을 시작하지 않는다.
2. **영상 분석** — `rp-youtube`를 그 SKILL.md대로 실행한다(전사본 확보 → 전문 Read → **STT 정규화** → 구조 복원 → 분석). 접근 불가(멤버십 등)·자막 없음이면 **여기서 중단**하고 사유를 알린다. ⛔ 장표를 억지로 만들지 않는다.
3. **원천 검증·보강 조사** — §원천 검증.
4. **레퍼런스 로드** — `rp-deck`의 `template.html` + `design-rules.md` + `visual-patterns.md`를 Read한다. (매 실행)
5. **기존 문서 확인 (보강/신규)** — `rp-deck` §보강 vs 신규. 같은 영상·같은 주제 덱이 이미 있으면 보강한다.
6. **설계·생성** — `rp-deck` §워크플로우 5~8을 따르되 §장표 추가 요건을 함께 지킨다.
7. **인덱스·린트·독립 리뷰** — `rp-deck` §워크플로우 9~11 그대로. 리뷰는 **작성자가 아닌 새 서브에이전트**로 2라운드, 건당 10분 상한.
8. **적재** — `rp-deck` §워크플로우 12. 커밋 → **push 성공까지 확인**. 실패 시 중단·보고.
9. **옵시디언 Ingest** — 이 스킬은 **항상 조사를 동반하므로 topic 모드로 취급**한다. `rp-deck` §옵시디언 규칙 그대로(`obsidian: false`면 묻지 않고 스킵, 키 없으면 딱 한 번 질문). `sources/`에 **전사본과 원천 대조표를 함께** 남긴다.
10. **오픈·보고** — 생성 HTML을 `open`. 영상 제목·장 수·검증 건수·불일치 건수·적재 위치를 한 줄로 보고한다.

## 원천 검증

영상이 인용한 문서를 **직접 열어** 수치·공식·문구를 대조한다. 자동자막 정규화로도 못 잡는 오류가 여기서 걸린다.

1. **검증 대상 뽑기** — `rp-youtube` 출력의 "영상이 인용한 출처" + "수치·공식" + "검증이 필요한 지점"을 목록으로 만든다.
2. **원문 확인** — 각 항목을 WebFetch로 직접 읽는다. URL을 모르면 WebSearch로 **공식 출처**(프로젝트 위키·벤더 공식 문서·표준 문서)를 먼저 찾는다. ⛔ 블로그 재인용으로 원천을 대신하지 않는다.
3. **대조표 작성** — 항목마다 판정을 붙인다.

   | 판정 | 뜻 | 장표 처리 |
   |------|-----|-----------|
   | `일치` | 원문이 영상 주장을 그대로 뒷받침 | 그대로 싣고 출처 표기 |
   | `보강` | 원문에 영상이 생략한 조건·맥락이 있음 | 그 조건을 함께 싣는다 |
   | `불일치` | 원문과 다르거나 원문에 없음 | **원문을 정답으로** 싣고, 영상과 다르다는 사실을 한 줄로 밝힌다 |
   | `확인불가` | 원천을 찾지 못함 | 싣되 "영상 화자의 주장"으로 귀속하고 단정하지 않는다 |

4. **보강 조사** — 영상이 다루지 않았지만 독자가 바로 부딪힐 실무 항목(설정 키 기본값, 버전별 차이, 운영 주의점)을 공식 문서에서 확인해 보탠다. **주제 범위를 넘는 확장은 하지 않는다** — 영상의 주제를 실무에서 쓰는 데 필요한 만큼까지.

## 장표 추가 요건

`rp-deck`의 모든 규칙에 더해 이 스킬만의 요건이다.

- **표지에 출처 영상** — 제목·채널·업로드일·재생시간을 표지나 두 번째 장에 밝힌다. 이 장표가 누구의 강의에서 나왔는지 감추지 않는다.
- **주장마다 타임스탬프** — 영상에서 온 주장에는 `[MM:SS]`를 남긴다(각주 또는 캡션). 원본으로 돌아갈 길을 끊지 않는다.
- **출처 장 필수** — 마지막 부근에 원천 문서 링크 목록 장을 둔다. 영상 링크 + 검증에 쓴 공식 문서 URL을 모두 적는다.
- **불일치는 숨기지 않는다** — `불일치` 판정 항목은 "영상은 A라고 했지만 원문은 B예요" 형태로 한 줄 명시한다. 조용히 고쳐 싣지 않는다.
- **영상의 말투를 옮기지 않는다** — 전사본은 구어체다. 장표 카피는 `rp-deck` §6 토스 톤(해요체·완결 주장문)으로 다시 쓴다.
- **분량은 주제 복잡도에 맞춘다** — 영상 길이에 비례시키지 않는다. 사용자가 장 수를 지정했으면 그 수를 목표로 하되, 이해에 필요한 내용은 줄이지 않는다.

## 절대 규칙

- **⛔ 접근 게이트 우회 금지** — 멤버십·Premium·비공개 영상은 `rp-youtube` 규칙대로 중단한다. 장표를 만들려고 우회하지 않는다.
- **⛔ 자막 없으면 장표 없음** — 자막이 없어 내용을 확인할 수 없으면 제목·설명으로 장표를 지어내지 않는다. 중단하고 알린다.
- **⛔ 정규화·검증 생략 금지** — STT 정규화(`rp-youtube` §전사본 정규화)와 원천 검증(§원천 검증)은 둘 다 필수다. 장표는 남아서 인용되므로, 깨진 숫자를 그대로 싣는 것이 이 스킬의 가장 큰 실패다.
- **원천이 영상보다 우선** — 원문과 영상이 다르면 원문을 싣는다. 화자의 권위로 원문을 덮지 않는다.
- **⛔ 스킬 규칙을 기억으로 대체 금지** — `rp-youtube`·`rp-deck`의 `SKILL.md`와 레퍼런스를 매 실행 실제로 Read한다. 요약본으로 진행하지 않는다.
- **타깃 레포는 명시 입력만** — `.rp-deck.json` 또는 이번 실행의 사용자 명시. ⛔ git remote·추측 금지. 없으면 한 번 묻고, 답이 없으면 로컬 생성(푸시 없음).
- **독립 리뷰 필수** — push 전 작성자가 아닌 새 서브에이전트가 2라운드 리뷰. 건당 10분 상한, 초과는 비차단 스킵.
- **옵시디언은 조사 원본까지** — vault가 설정돼 있으면 정규화 전사본과 원천 대조표를 `sources/`에 남긴다. 장표만 남기고 근거를 버리지 않는다. ⛔ 민감정보 기록 금지.
- **push까지 완료** — 레포 모드는 커밋 후 push 성공을 확인한다. 캐시는 다음 실행에서 `reset --hard`로 날아가므로 로컬에만 남기면 유실된다.
