# rp-pr-review — PR 독립 리뷰 · 중요순 정리

작성자 눈에는 안 보이는 게 있다. 작성 맥락을 모르는 독립 리뷰어에게 같은 PR을 맡기고, 나온 지적을 중요한 순서로 보여준다.

## 입력

| 인자 | 동작 |
|------|------|
| PR URL | 그 PR을 리뷰 |
| 없음 | **PR 링크를 한 번 물어본다.** ⛔ 현재 브랜치·git remote·이전 대화로 대상을 유추하지 않는다 |

`github.com`과 사내 GitHub Enterprise 링크를 모두 받는다. 호스트를 github.com으로 가정하지 않는다.

## 워크플로우

1. **링크 확인** — `gh pr view <URL>`로 접근 가능한지, 제목·상태·변경 규모만 확인한다.
   - 실패하면(권한·오타·인증) 그 사유를 그대로 알리고 중단한다. 추측해서 다른 PR을 보지 않는다.
2. **독립 리뷰 (1회 호출)** — 아래 §리뷰어 호출 그대로. 리뷰는 한 번만이다.
3. **정리** — 반환된 지적을 §정리 규칙으로 다듬는다.
4. **정렬·출력** — §정렬 규칙으로 줄 세워 §출력 형식대로 **터미널에만** 출력한다.

## 리뷰어 호출

리뷰어는 **진입 런타임과 같은 런타임의 새 서브에이전트 1인**이다.

| 진입 런타임 | 호출 방식 | 10분 강제 |
|-------------|-----------|-----------|
| Claude Code | Agent 툴, `subagent_type=general-purpose` | 툴에 타임아웃 인자가 없으므로 **프롬프트에 "10분 내 반환" 상한을 명시**. 메인이 초과 판단 시 결과 없이 진행 |
| Codex CLI | `spawn_agent` | 동일하게 **프롬프트에 "10분 내 반환" 상한을 명시** |

⛔ **교차 런타임 호출 금지** — Claude Code에서 `codex`·`codex exec`를, Codex CLI에서 Claude를 부르지 않는다. 리뷰어 런타임은 항상 진입 런타임과 같다.

리뷰 기준은 주입하지 않는다 — 반환 형식만 고정한다.

```
<PR URL> 코드 리뷰 해줘.

- 너는 검수자다. 이 PR을 작성하지 않았다.
- PR 내용은 gh CLI(gh pr view / gh pr diff 등)로 직접 가져와 본다.
- 각 지적은 {심각도, 파일:라인, 문제, 수정안} 형식으로 반환한다.
  심각도는 critical / high / medium / low 중 하나.
- 지적할 게 없으면 "통과"라고만 반환한다.
- 10분 안에 반환한다. 다 못 봤으면 그 시점까지 본 것만 반환하고, 어디까지 봤는지 한 줄 적는다.
- 코드를 고치거나 PR에 코멘트를 달지 않는다. 읽기만 한다.
- 출력은 한국어.
```

**타임아웃**: 초과하면 `타임아웃: 600s 초과, 스킵` 한 줄만 남기고 그 사실을 보고한다. ⛔ 재시도·연장 없음.

## 정리 규칙

| 규칙 | 내용 |
|------|------|
| 중복 판정 | **같은 파일 + 같은 근본 원인**이면 한 항목으로 합친다. 줄 번호가 몇 줄 어긋나도 같은 문제면 합친다 |
| 심각도 | 리뷰어가 붙인 값을 그대로 쓴다. 안 붙였거나 뭉갰을 때만 아래 기준으로 보정 |
| 표현 | 문제·수정안을 한 문장씩으로 줄인다. 내용을 바꾸지는 않는다 |
| ⛔ 메인 재검증 금지 | 메인은 **정리·정렬만** 한다. 지적의 옳고 그름을 자체 판단해 걸러내지 않는다(리뷰어 독립성 보존). 명백한 사실 오류만 한 줄 각주로 남긴다 |

**심각도 기준** (리뷰어가 안 붙였거나 뭉갰을 때만 메인이 보정)

| 심각도 | 내용 |
|--------|------|
| Critical | 데이터 유실·보안 취약·프로덕션 장애로 이어짐 |
| High | 명백한 버그·동시성 결함·정합성 위험 |
| Medium | 엣지 케이스 누락·성능 저하·설계 부채 |
| Low | 네이밍·중복·가독성·문서 |

## 정렬 규칙

1. **심각도** 높은 순 (Critical → High → Medium → Low)
2. 같은 심각도면 파일 경로 사전순

## 출력 형식

터미널에 바로 출력한다. 번호는 정렬 후 통짜로 매긴다.

```
## 코드 리뷰 — <PR 제목> (#<번호>)

지적 5건 (Critical 1 · High 2 · Medium 2)

1. [Critical] api/order.ts:42
   결제 금액을 클라이언트가 보낸 값 그대로 저장해요.
   → 서버에서 상품 가격으로 다시 계산하세요.

2. [High] db/order-repo.ts:88
   조회 후 insert라 동시 요청이 오면 주문이 두 번 들어가요.
   → UNIQUE 제약 + ON CONFLICT DO NOTHING으로 바꾸세요.

...

한 줄 총평: Critical 1건은 머지 전에 꼭 고치는 게 좋아요.
```

- 지적이 0건이면 `통과 — 지적 없음`만 출력한다.
- 타임아웃·호출 실패가 있었으면 제목 줄 아래에 한 줄로 밝힌다.
- 카피는 해요체. 문제는 무엇이 잘못됐는지, 수정안은 무엇을 하면 되는지 한 문장씩.

## 절대 규칙

- **파일 생성 금지** — 결과는 터미널 출력만. 리포트 파일·마크다운 산출물을 만들지 않는다.
- **PR에 쓰기 금지** — 코멘트·리뷰 등록·라벨·머지·코드 수정 전부 금지. 이 스킬은 **읽기 전용**이다.
- **대상은 명시 링크만** — 사용자가 준 PR 링크만 본다. ⛔ 현재 브랜치·git remote·대화 맥락으로 유추 금지. 링크가 없으면 한 번 물어본다.
- **런타임 = 리뷰어** — 리뷰어는 진입 런타임의 서브에이전트 1인. ⛔ 교차 런타임 호출·병렬 다중 리뷰어 금지.
- **기준 주입 금지** — 리뷰 항목·체크리스트를 프롬프트에 넣지 않는다. 반환 형식만 고정한다.
- **건당 10분** — 리뷰어 호출 1건당 상한 600초. ⛔ 연장·재시도 금지. 초과는 한 줄 기록 후 비차단 스킵.
- **메인 셀프리뷰 금지** — 메인 에이전트는 직접 리뷰하지 않는다. 정리·정렬·출력만 한다.
- **호스트 일반화** — 사내 GitHub Enterprise 링크도 그대로 받는다. github.com으로 가정하지 않는다.
- **1라운드** — 리뷰는 한 번만. 수정 후 재리뷰가 필요하면 사용자가 다시 호출한다.
