# rp-youtube-channel — 채널 영상 목록 · 후보 추리기

채널 하나에 영상이 수백 개다. 매번 전부 훑을 수도, 어제 뭘 했는지 기억할 수도 없다. 이 스킬은 **아직 안 다룬 영상 중 실제로 장표를 만들 수 있는 것**만 앞에서부터 추려 준다. 하루 한 편씩 자동으로 돌리는 파이프라인의 첫 단계다.

## 레퍼런스

| 파일 | 역할 |
|------|------|
| [`scripts/list_channel.py`](scripts/list_channel.py) | 채널 해석 → 최신순 목록 → 상태 대조 → 순차 프로브 → 후보 JSON·표 (stdlib + yt-dlp) |

## 입력

| 인자 | 동작 |
|------|------|
| 핸들 (`@name`) | 그 채널의 videos 탭 |
| 채널 URL (`youtube.com/@name`·`/channel/UC…`) | 그 채널 |
| 영상 URL (`watch?v=`·`youtu.be/`) | 그 영상의 업로더로 채널을 역산 |
| 등록된 별칭 | 이전에 `--alias`로 등록해 둔 이름 |
| 없음 | 등록된 채널 목록을 보여주고, 어느 채널인지 물어본다 |

⛔ **대상은 명시 입력 또는 등록된 별칭만.** git remote·이전 대화·추측으로 채널을 정하지 않는다.

## 상태를 어디에 두나

로컬에만 두면 캐시 초기화·기기 교체로 사라진다. **장표가 올라가는 레포(대상 루트)에 둔다.**

| 위치 | 내용 |
|------|------|
| `<root>/.rp-youtube/salt` | 장표 메타용 해시 솔트. 없으면 처음 실행할 때 만든다 |
| `<root>/.rp-youtube/registry.json` | 채널 별칭·videos URL·제목 제외 정규식 |
| `<root>/.rp-youtube/channels/<slug>.json` | 이 채널의 제외·보류 기록, 마지막 조회 시각 |
| 각 장표의 `<meta name="deck-source-ref">` | **이미 장표로 만든 영상** (솔트 해시, 상태 파일과 별개의 SSOT) |

- "이미 만든 것"을 상태 파일이 아니라 **장표 자체에서** 읽는 이유: 상태 파일이 유실되거나 손으로 지워져도 게시된 장표를 스캔하면 복구된다.
- 그래서 `rp-youtube-deck`은 장표를 만들 때 이 메타를 반드시 넣는다. 없으면 같은 영상을 다시 고른다.
- 상태 파일은 **장표를 만들지 못한 이유**만 담는다 — 이건 장표가 없으니 다른 데 기록할 곳이 없다.

### 왜 영상 ID가 아니라 해시인가

장표 HTML은 공개 사이트로 나간다. 영상 ID를 그대로 넣으면 소스만 봐도 출처 유튜브 영상을 알 수 있어 `rp-youtube-deck` §영상 흔적 지우기가 무의미해진다.

- 값은 `sha256("<솔트>:<영상ID>")`의 앞 16자다.
- **솔트가 있어야 하는 이유**: 솔트 없이 해시만 쓰면 채널을 짐작한 사람이 그 채널 영상 ID를 전부 해시해 맞춰볼 수 있다. 솔트는 레포 안에만 있고 공개 사이트로 나가는 건 해시뿐이다.
- 장표에 넣을 값은 이 스크립트가 계산해 준다.

  ```
  python3 <스킬경로>/scripts/list_channel.py --root <대상루트> --ref <영상ID>
  ```

- ⛔ **솔트를 잃어버리면 기존 장표와 대조가 끊긴다.** 전부 미처리로 보여 같은 영상을 다시 만든다. `.rp-youtube/`를 통째로 지우지 않는다.

**대상 루트**는 `rp-deck`과 같은 규칙으로 정한다. 실행 프로젝트 루트 `.rp-deck.json`의 `repo`가 있으면 그 캐시(`~/.rp-deck/repos/<owner>__<name>`), 없으면 `<cwd>/docs/decks`. ⛔ 작업 전 캐시를 원격 최신으로 강제 동기화한다(`git fetch` + `reset --hard`) — stale 상태로 판단하면 같은 영상을 두 번 고른다.

## 왜 순차 프로브인가

목록 조회(`--flat-playlist`)는 **ID와 제목만** 준다. 공개일·길이·자막·멤버십 여부는 영상마다 개별 조회(프로브)해야 나오고 건당 1~2초가 든다. 수백 개를 다 프로브하면 몇 분씩 걸린다.

그래서 **최신순으로 훑으며 이미 처리·제외된 것을 건너뛰고, 남은 것만 앞에서부터 프로브해 `--limit`을 채우면 멈춘다.** 보통 10건 안팎만 프로브하고 끝난다.

## 제외 규칙

| 대상 | 판정 | 기록 |
|------|------|------|
| 멤버십·Premium·비공개·로그인 필요 | `availability` 필드 | **영구 제외** — 다시 프로브하지 않는다 |
| 자막이 하나도 없음 (수동·자동 모두) | 자막 트랙 목록 | **보류** — 나중에 생길 수 있어 `--retry-deferred`로 되살린다 |
| 90초 이하 | 길이 | 영구 제외 (쇼츠) |
| 조회 실패 | yt-dlp 오류 | **기록하지 않는다** (§일시적 실패) |
| 모음편 제목 | `registry.json`의 `exclude_title` 정규식 | 기록하지 않고 매번 건너뜀 |

- 쇼츠는 별도 탭(`/shorts`)이라 videos 탭만 읽으면 대부분 자연히 빠지고, 길이 조건이 남은 것을 잡는다.
- 모음편(기존 영상을 이어 붙인 것)은 개별 영상과 내용이 겹친다. 표기가 채널마다 다르므로 **정규식은 기본값일 뿐이고 `registry.json`에서 채널별로 바꾼다.** 필요 없으면 빈 문자열로 둔다.

## 일시적 실패는 상태로 굳히지 않는다

레이트리밋·네트워크 오류로 조회에 실패한 영상을 보류로 기록하면, 멀쩡한 영상이 다음 실행에서도 영영 후보에 오르지 않는다. **조회 실패는 이번 실행에서만 건너뛰고 상태에 남기지 않는다.**

- 연속 3건 실패하면 레이트리밋으로 보고 **그 자리에서 멈춘다.** 채널 전체를 훑으며 실패를 쌓지 않는다.
- 프로브 사이에 기본 1초를 쉰다(`--sleep`). 빠르게 연속 요청하면 유튜브가 막는다.
- 중단되면 표 아래에 그 사실을 알린다. 잠시 뒤 다시 실행하면 된다.

## 워크플로우

1. **대상 루트 확인·최신화** — `.rp-deck.json`을 읽고 캐시를 원격 최신으로 동기화한다. (§상태를 어디에 두나)
2. **채널 해석** — 인자가 없으면 `--list`로 등록된 채널을 보여주고 물어본다.
3. **실행**

   ```
   python3 <스킬경로>/scripts/list_channel.py <채널> --root <대상루트> --out <작업디렉터리> --limit 10
   ```

   - **작업 디렉터리**: 스크래치패드가 있으면 그 아래 `rp-youtube/`, 없으면 `~/.rp-youtube/work/`. ⛔ 사용자 레포에 후보 JSON을 만들지 않는다.
   - 처음 쓰는 채널이면 `--alias <짧은이름>`으로 등록해 다음부터 그 이름으로 부른다.
   - 종료 코드: `0` 후보 있음 / `2` 후보 없음 / `3` 채널 해석 실패 / `4` yt-dlp 설치 실패.
4. **보고** — 스크립트가 낸 표를 그대로 보여준다. 후보 JSON 경로도 함께 알린다.
5. **상태 커밋 (레포 모드)** — 이번 실행에서 `excluded`·`deferred`가 늘었으면 `<root>/.rp-youtube/`만 `git add` → 커밋 → push한다. 늘지 않았으면 커밋하지 않는다.
   - ⛔ 상태만 커밋한다. 장표 파일·index는 이 스킬이 건드리지 않는다.
   - push 실패는 중단·보고. 캐시는 다음 실행에서 `reset --hard`로 날아가므로 로컬에만 남기면 유실된다.

## 출력

터미널 표 + 후보 JSON 두 가지를 낸다. 사람은 표를 보고, 다음 스킬은 JSON을 읽는다.

```
## <채널> — 후보 N건 (전체 180 · 완료 3 · 제외 5 · 보류 2)

| # | 제목 | 공개일 | 길이 | 자막 | 링크 |
|--:|------|--------|------|------|------|
| 1 | … | 2026-08-08 | 17:26 | auto/ko-orig | https://youtu.be/… |
```

후보 JSON(`<out>/<slug>-candidates.json`) 구조 — 다음 스킬이 소비하는 인터페이스다.

| 키 | 내용 |
|----|------|
| `channel`·`alias`·`videos_url` | 채널 식별 |
| `total`·`done`·`excluded`·`deferred`·`probed` | 이번 실행의 집계 |
| `candidates[]` | `id`·`source_ref`(장표 메타에 넣을 해시)·`title`·`upload_date`·`duration`·`view_count`·`subtitle_kind`·`subtitle_lang`·`url` |
| `probe_errors`·`throttled` | 조회 실패 건수와 레이트리밋 중단 여부 |

`candidates`는 **최신순**이다. 하루 한 편 고르는 쪽은 맨 앞을 집으면 된다.

## 절대 규칙

- **⛔ 접근 게이트 우회 금지** — 멤버십·Premium·비공개는 제외로 기록하고 넘어간다. 쿠키 추출·계정 로그인·미러 탐색 전부 금지.
- **⛔ 자막·메타만 조회** — 영상·오디오는 받지 않는다.
- **⛔ 상태는 원격에** — 상태 파일은 대상 루트(장표 레포)에 두고 push까지 완료한다. 로컬 캐시에만 남기면 다음 실행의 `reset --hard`로 사라져 같은 영상을 다시 고른다.
- **작업 전 원격 최신화 필수** — 판단 전에 캐시를 `fetch` + `reset --hard`한다. stale 상태로 고르면 중복이 난다.
- **"이미 만든 것"은 장표에서 읽는다** — 상태 파일에 완료 목록을 따로 두지 않는다. 두 곳에 적으면 어긋난다.
- **⛔ 장표 메타는 해시로** — `deck-source-ref`에 영상 ID를 그대로 넣지 않는다. 장표 HTML은 공개되므로 ID가 그대로 드러나면 출처를 감춘 의미가 없다. 값은 `--ref`로 계산한다.
- **⛔ 일시적 실패를 상태로 기록하지 않는다** — 조회 실패는 이번 실행에서만 건너뛴다. 연속 3건이면 레이트리밋으로 보고 중단한다. (§일시적 실패)
- **대상은 명시 입력만** — 핸들·URL·등록 별칭만 인정한다. ⛔ 추측·자동 지정 금지. 인자가 없으면 등록 목록을 보여주고 물어본다.
- **프로브 상한을 지킨다** — `--limit`을 채우거나 `--max-probe`에 닿으면 멈춘다. 채널 전체를 훑지 않는다.
- **작업 파일은 레포 밖에** — 후보 JSON은 스크래치패드나 `~/.rp-youtube/work/`에 둔다. 레포에는 `.rp-youtube/` 상태만 들어간다.
- **채널을 코드에 박지 않는다** — 특정 채널의 핸들·URL·이름을 스킬 파일이나 스크립트에 하드코딩하지 않는다. 전부 인자와 `registry.json`으로 받는다.
